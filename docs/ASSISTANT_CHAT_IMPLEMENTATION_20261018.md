### 使用方法

1. 对目标 MySQL 执行 `sql/migrations/20261018_assistant_chat.sql`，与 `sql/schema.sql` 中五表一致。
2. 本地配置设置 `LEARNHUB_ASSISTANT_CHAT_ENABLED=true`、`LEARNHUB_AI_MODE=FAKE`。此入口默认关闭，不自动修改用户本地配置。
3. 由用户正常启动后端。登录后创建 `POST /api/assistant/conversations`，请求 `{"courseId":课程编号,"title":"Redis学习"}`。
4. `POST /api/assistant/conversations/{id}/runs` 输入 `message` 和新的小写 UUID `clientRequestId`，阶段 2 起返回 `text/event-stream`。重复发送相同请求不会创建第二次运行。消息通过 `GET /api/assistant/conversations/{id}/messages` 读取。
5. `POST /api/assistant/runs/{id}/cancel` 取消本人运行；`GET /api/assistant/runs/{id}` 查询终态。所有请求使用 Authorization 请求头，令牌不进入 URL。

## 阶段 2：独立工作区与 Fake SSE

流协议使用 fetch POST + Authorization header，包含 `eventId/runId/seq`。`accepted` 后不会自动重放生成；断流查询 run，重复请求只读取原状态。Fake 草稿明确标记模拟、尚未最终确认；成功才回取正式历史，失败/取消清空草稿，终态后忽略迟到 delta。读取器支持 UTF-8 跨包、CRLF、多事件和大小限制；EOF 未以空行终止的事件判为截断，避免假完成。

停止先请求服务端取消，再 AbortController 中止浏览器连接。服务端断连先中断本地任务，再写取消标记；提交前还检查连接是否已终止。最终数据库条件更新处理与取消的竞争。已建立 SSE 的 ASYNC 完成分派只允许终止响应，撤权由运行内复核发结构化错误；这个例外限定服务器内部标记、POST、指定 runs 路径。普通 DeferredResult 继续在 ASYNC 分派重新鉴权。

## 阶段 3：LangChain4j 流式与有界上下文

生产 POM 使用 LangChain4j BOM 1.22.0 的普通 Java 模块，Spring 手工装配，不使用 Starter、不升级 JDK 17 / Boot 3.3.5。新路径由 `LEARNHUB_ASSISTANT_LANGCHAIN_ENABLED=true` 与 `LEARNHUB_AI_MODE=DEEPSEEK` 联合启用；聊天入口仍需要 `LEARNHUB_ASSISTANT_CHAT_ENABLED=true`。密钥沿用本地 `LEARNHUB_DEEPSEEK_API_KEY`，生产地址固定 DeepSeek 官方 API。旧课程卡片同步客户端暂作迁移对照，尚未移除。

每次从 MySQL 正式历史选取最近两轮完整问答，整条复核来源后放入请求独享的 `MessageWindowChatMemory`；窗口淘汰不删正式历史。移除历史旧引用编号，再将历史依赖与当前 BM25 来源加入本轮证据账本。历史依赖超过证据上限时整轮排除，不能保留正文却丢弃依赖。来源去重忽略检索 score，仍比较稳定字段；材料移课也会使旧引用失效。

流式直接消费 `OpenAiStreamingChatModel` 回调，使用普通正文及 `[E1]` 段末标记，终态检查结束原因、完整文本一致性、引用存在、段末引用、外链和 4000 字符上限。暂不把旧整段 JSON 输出协议用于增量正文。首批立即转发，随后至多缓存 100ms 或约 256 字符再执行授权/版本检查；回调队列有界，不在供应商回调线程做 JDBC。最终提交仍重新核对本人会话、材料与运行状态。正式来源事件发送前再次核对登录、本人会话和证据，使用本次复核返回的引用；若提交后撤权，清空草稿且不发送来源/成功事件，不把已提交的数据库终态降级。

生产 HTTP SPI 复用应用级 JDK HttpClient，网络池与阻塞流读取池分别有界；每个运行仅借用独立的 operation，取消 A 不会关闭 B。应用关闭时清理两个池。`AssistantIoScope` 取消绑定到 HTTP future/响应流，首字前也可取消，限制成功/错误响应字节和队列。JDK 17 的底层 selector 没有公开 close 方法，本实现限制为每个生成器实例一个，而不是每次运行新建。模型请求禁用原始日志、隐藏推理与自动付费重试；每次请求前持久化保守预留，收到完整 usage 后记录实际值。缺 usage、断流、取消均不提交成功答案，未知用量保留预留。

实际验证：阶段 3 定向 25 项通过，随后追加严格请求解析/包装 HTTP 错误回归的模型 7 项通过；最终根 `mvn verify` 360 项，失败 0、错误 0、跳过 69。隔离 MySQL 专项 21 项全部通过（持久化 11、历史 5、会话 5），新增测试证明取消后的预留记录不被迟到 usage 覆盖，临时容器已清理。普通回归中的 MySQL 11 项与真实模型 1 项默认跳过，分别已通过隔离脚本和下述受控烟测执行；其余基础设施跳过保持原有开关。最终 JAR 中 Jackson 统一 2.17.2，LangChain4j 普通模块 1.22.0，响应式模块 1.22.0-beta32。

## 阶段 4：框架切分与授权 BM25 RAG

`KnowledgeChunker` 已在真实导入链使用 `DocumentSplitters.recursive(600, 60)`；这里的单位是 UTF-16，不是模型 Token。按原 scene 保存标题与全局顺序。框架输出若有孤立代理项、超长或无法证明覆盖原正文，则整场景使用 code-point 边界安全回退；单块不超过 600 UTF-16 单位、相邻重叠不超过 60，拒绝原输入的非法代理项。覆盖检查采用有界迭代，10 万重复中文有 2 秒回归上限，避免重复文本回溯爆炸。

策略常量 `langchain4j-recursive:utf16:max=600:overlap=60:unicode-fallback=codepoint-v1` 进入内容哈希。同一来源重导入时，旧哈希触发新材料版本和新 chunk ID，旧切片不改写。数据库未保存原 scenes，部署代码不会自动重切旧资料；须从已审校 catalog 重新导入。MySQL 先记录新版本，ES 完整写入、refresh 后才标记 indexed_version；同步失败期间旧版本不可用于回答，任务补偿后恢复，不能称为无缝切换。

聊天使用 LangChain4j `ContentRetriever` / `DefaultRetrievalAugmentor` / 自定义 `ContentInjector`：用户、课程和会话从服务端 scope 捕获，Retriever 仅调用既有 `KnowledgeRetrievalService` 一次，不绕过授权 facade 直查 ES。保留文档/版本/块/课程/课时/标题等 metadata，自定义 Injector 输出原有 question/evidence JSON，增强后的 `chatMessage()` 实际进入 ChatMemory 和模型。显式使用当前有界运行 worker，关闭额外 offload，不使用框架默认 cached 线程池。

历史两轮先逐条验证、最多分配 15 个不同材料依赖，本轮召回最多 5 条；证据账本整体最多 20。即使当前召回为空，合法历史依赖仍由 Injector 注入。取消、历史失效、检索后版本变化或证据超额均在请求模型前失败关闭。纯问候使用固定友好文案；确实没有课程证据时固定拒答，不编造引用、不消耗模型额度。

实际验证：初次针对切分/授权检索/生成器/历史/证据的 46 项全部通过；真实知识基础设施 9 项全部通过，其中包含 6 份已审校 catalog、18 个场景在随机隔离 MySQL/ES 中导入及现有 8 条开发用例回归。另验证相同正文旧哈希升级、新旧 chunk ID 分离、旧切片可审计、旧证据失效、旧 ES 版本清除和失败补偿。该开发集是已见回归，不是新留出集。临时 MySQL 已清理，测试只操作自有随机索引，业务库与业务索引未重导入。

最终根 `mvn verify` 377 项，失败 0、错误 0、跳过 71；知识基础设施 9 项在普通回归默认关闭，已由上述隔离专项实际通过。测试后知识索引 alias 与本次临时 MySQL 均无残留。`git diff --check` 通过。`StageAMaterialImportIntegrationTest` 保持关闭，未把隔离材料验证称为业务库重导入。

## 阶段 6：框架自主工具与完整历史依赖
