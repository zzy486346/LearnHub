## 2. 业务及兼容规则

### 课程与学习

“下架”采用停售语义：`PUBLISHED` 对外开放；`OFFLINE` 仅已付款用户可访问；`DRAFT` 对普通用户不可访问，即使存在历史订单也不开放。已付款订单重复确认保持幂等。

创建订单和付款在事务中锁定仍为 `PUBLISHED` 的课程行，与管理端上下架更新串行，避免检查上架状态后又跨过下架更新继续付款。

学习完成标记一旦为真，普通进度保存不会清除。播放位置不是历史最大播放位置，允许用户重新观看；按服务端生成保存记录的时间选择较新的位置，同一时间精度内按数据库实际写入顺序处理。前端不提供可信客户端时间，服务端也不接受客户端覆盖该时间。

### 秒杀重试

只有 `FAILED` 且已完成库存补偿的订单可以重新进入 `PENDING`。重试更新请求编号、发布状态、次数及失败信息，并通过条件更新防止并发重复激活。未补偿失败、处理中和成功订单不允许重复创建。

消息使用各次尝试的请求编号隔离。旧请求到达时不再为该旧尝试扣库存或发券，旧失败处理也不能补偿当前尝试。

### 媒体访问与升级

- 通用媒体上传只允许为当前用户上传头像；头像专用入口和管理员课程视频上传入口保留。其他业务类型需使用专用授权入口，不再允许普通用户自行声明课程关联。
- 新预签名 PUT 的目标为临时键，完成时核对大小和类型，再使用 `copySourceIfMatch` 与 `forbidOverwrite` 转存正式键。原 PUT 无权覆盖正式键。
- 真实 SDK 的离线签名测试确认 `Content-Length` 不在签名头中，不能把申请大小视为 OSS 签名强制约束；安全检查在完成和转存阶段实施。
- 升级前的旧版 `UPLOADING` 上传票据被拒绝并要求重新上传，避免继续发布可被原签名覆盖的对象。
- 升级前已经 `READY` 的对象若仍有未过期的旧 PUT 签名，应用不能撤销该签名，需等待原有效期到期。
- 生成签名 URL 不会修改 Bucket ACL。课程对象仍须配置私有访问，不能用公开 Bucket 的 ACL 作为课程权限保护。

### 本机复现命令

```powershell
$env:DOCKER_CONTEXT = 'default'
pwsh -NoProfile -File scripts/admin/verify-course-management.ps1
pwsh -NoProfile -File scripts/auth/verify-infrastructure.ps1
pwsh -NoProfile -File scripts/seckill/verify-infrastructure.ps1
& 'D:\Android\apache-maven-3.9.10\bin\mvn.cmd' test
& 'D:\Android\apache-maven-3.9.10\bin\mvn.cmd' verify
```
