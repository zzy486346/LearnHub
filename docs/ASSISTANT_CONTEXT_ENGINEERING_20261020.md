## 调用链审计

- `LangChainChatGenerator.prepare`：校验 owner/conversation、guard/IO scope，MySQL 取 12 条候选，选择最多两轮完整已完成对话，恢复依赖后进入授权 RAG。
- `ChatHistoryService.verify` 调用 `ChatEvidenceCodec.restoreInto`，重新验证材料、课程/目录/进度快照和偏好；失效回答连同对应用户问题不进入上下文。
- `AuthorizedCourseRag` 使用当前身份/课程检索，`EvidenceBook` 合并与去重，MySQL 复核权限、正文和版本；RRF 排名不是绝对相关度。
- Agent 的 `beforeRound` 每次重新渲染当前证据和偏好，按完整输入加工具 schema 和固定开销预留预算；`reserveModel` 以 UTF-8 字节作为保守 Token 上界，输出另预留。每次调用累计扣减，未知用量不退款。
- 工具执行、模型重发、流式段落与最终结果继续执行 `guard.check/book.check/io.remaining`。不得因裁剪或摘要跳过这些检查。

## 改造计划与验收门槛

1. 先跑现有 HTTP Mock/依赖复核测试，冻结新的上下文验收规范；保留失败证据。这里的规范不是未见真实模型测分结果。
2. 提取一个确定性上下文规划器：保留固定规则和当前任务，按输入字节与剩余运行预留分配历史空间；整轮选入/丢弃，完整 JSON，保留工具调用/结果配对。仅指代追问带入已复核上一问题，切换主题不拼接。逐次模型调用再规划，统计只含数量、字节与原因。
3. 压缩较早回合时先用确定性、每次重建的会话摘要，不新增数据库/模型调用。摘要只记录有来源序号的用户原话片段，区分用户自述与事实；依赖失效整轮移除，近期完整回合优先。明确其有限候选窗口、无语义总结能力。
4. 证据不足单独处理和测试：空证据可确定拒答，非空弱证据需要支持性评估；不得凭 RRF 分数设未经评测的通用阈值。协议验证与真实答案质量分别报告。
5. 每项逻辑变更运行专项及根 `mvn test` / `mvn verify` 后中文 Conventional Commit。记录实际执行/跳过数与剩余验收边界；付费额度不足不阻碍本地协议与安全验收，但不能宣称真实模型质量通过。

## 动态上下文第一步

- 新增 `ChatContextPlanner`，统一计算消息、JSON 转义、工具 schema 和 2048 字节协议开销；容量取本地输入上限与运行剩余预留减输出的较小值。这延续现有 `reserveModel(inputBytes, outputTokens)` 的字节作为 Token 上界策略，保守而非供应商精确分词。
- 历史候选由 12 条扩大至 48 条，先按 owner/course/已完成配对与依赖复核，再以剩余空间的一半选入完整回合，剩余空间留给工具观察。历史正文和依赖一起计费，证据仍最多 20 条；同一材料仍由账本去重。预算不足不拆 JSON，也不拆工具链。
- 本轮材料优先通过实际 LangChain4j Augmentor 获取、验证和登记，随后恢复准入历史，统一按账本渲染当前输入。不是重复检索；RAG 内容验证仍执行，模型输入格式集中在 `currentMessage`，避免把最初的 JSON 快照当成工具后最新证据。
- 新增确定性 `ConversationQueryPlanner`。独立问题不拼接上一问；指代问题从已经通过依赖复核的候选中寻找最近明确问题。查询只用于召回，可能使用因输入预算未选入完整对话的问题，不把查询改写当事实；它不具备完整语义指代消解能力。
- Agent 每次发送前再次按当前已预留总数规划，先移除较早普通历史对；固定规则、当前问题、工具调用与结果、完整证据不做字符串截断。必要输入仍超限时在预留/HTTP 前失败。日志只记录模式、数量、预算和丢弃数。
- 专项 67 项全部实际通过，零失败/错误/跳过（首次新增测试编译发现两个 `Long` 参数错误，已修正后执行）。根 `mvn test` / `mvn verify` 分别通过：592 项，479 实际执行、113 条件跳过，零失败/错误；Mem0 deadline 测试本轮两次完整回归均通过。没有启用真实维护/付费验收测试。

## 可失效摘要第一步

- 新增 `ConversationSynopsis`：最多 4 条较早回合的用户原话摘录，每条至多 160 Unicode code points，明确 `USER_QUOTE`、`truncated`、用户/助手消息序号、消息哈希、依赖哈希和 `user-extract-v1`。它不总结助手事实、不推断用户已经掌握的知识，也不声称抽取了完整目标或待办。
- 近期完整回合优先；只尝试压缩早于完整保留窗口的其他已复核回合，完整依赖也计入预算。模型重发预算紧时先删除整条摘要，再删除较早完整回合。JSON 通过解析/序列化重建，不截断 JSON 字符串。
- 暂不新增持久化摘要表、覆盖游标、异步任务或 LLM 摘要调用。每次从最多 48 条当前正式消息重建，失败/取消不会推进任何摘要覆盖状态。范围仍有限，不能称为无限长会话记忆或语义摘要。
- 哈希用于追溯，实际失效保护来自 `ChatHistoryService.verify`、恢复完整 `ChatEvidenceCodec` 依赖及本轮 `EvidenceBook.check`。材料切版、撤权、偏好修改/忘记使整个相关回合无法进入摘要；已入选后发生变化则废弃本次回答。没有“删掉失效引用但继续发旧正文”的降级。
- 专项最终 66 项全部执行且通过（本批不含前批的 Spring 装配/RAG 7 项，数量不能直接相加）；根 `mvn test` / `mvn verify` 各 598 项、485 实际执行、113 条件跳过，零失败/错误。实际新增覆盖资料切版后摘要消失、偏好忘记后整轮失效、摘要先于近期回合裁剪，以及第二次模型调用按剩余预留在 HTTP 前失败。

## 证据不足与质量边界

- 在聊天运行最终 usage 中新增 `evidenceOutcome`，区分问候 `NO_COURSE_ANSWER`、服务端无材料 `NO_SOURCES_SERVER`、非空候选后的模型自报不足 `MODEL_REPORTED_INSUFFICIENT`、引用编号有效的模型回答 `MODEL_ANSWER_WITH_VALID_REFERENCES`。该字段不声称语义充分，不使用 RRF 分数阈值，也不增加模型调用。
- 首次回归复现拒答仍向历史页/来源 SSE 发布弱候选：`ChatHistoryServiceTest.refusalHidesWeakSourcesButStillRevalidatesTheirDependencies` 6 项中 1 项失败，实际返回 E1 材料。修复为先完整 `restoreInto`，再对固定拒答文案返回空展示来源；材料/偏好依赖仍保留在历史信封，撤权后仍整条限制。不能通过删除依赖掩盖变化。
- 普通流式与工具流式均增加“非空候选 + 模型拒答”HTTP Mock；检查固定不足文案、空展示引用、保留依赖、调用正常计费。`confirmedSources` 与历史页共用的出口同时修复。
- `validReferencesAreExplicitlyNotReportedAsSemanticallyVerifiedAnswers` 是负向质量探针：E1 只谈缓存互斥重建，Mock 却生成“Lua执行失败会自动回滚MySQL事务”。结构/编号校验仍接受并流出该句。**这是已复现的语义质量缺口，不是正确答案验收通过。** 当前并未实现独立的 claim→evidence 蕴含判断。
- 后续可先评审段落支持片段协议及逐字锚点校验，在流出段落前验证；但原文锚点仍不等于整段语义支持。不要用“加了提示词/合法 E# / 精确 quote”替代质量评测，也不要未经评测引入统一相似度阈值。真实模型批次仍需新的明确额度授权，当前台账不能绕过。
- 本阶段专项 63 项全部实际通过；最终根 `mvn test` / `mvn verify` 各 602 项、489 实际执行、113 条件跳过、零失败/错误。负向质量探针包含在测试数中，意味着诊断能复现并准确标识缺口，不能计为语义正确率通过。Mem0 deadline 竞争本轮未复现。
- 最终只读核验付费台账仍为 `calls=3/reservedTokens=11592`，本地 `hybrid=true`。本轮临时测试 JVM 均已退出，剩余 Java 进程启动于本轮工作之前，没有停止用户服务。没有保留测试后端；没有重启用户后端、合并或推送。
