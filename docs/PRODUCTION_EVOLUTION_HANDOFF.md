# LearnHub 现状与线上化扩展交接文档

> 文档用途：把当前 MVP 的真实实现状态、已知边界和后续线上化路线交给新的开发对话或开发者。  
> 项目名称：问课尚学（LearnHub）  
> 技术基线：JDK 17、Spring Boot 3、MyBatis-Plus、MySQL、Redis、RabbitMQ、Elasticsearch、Vue 3、TypeScript、Vite。  
> 代码基线：`main` 分支；本文编写前最后一个功能提交为 `439e8f4 fix: 修复问答发布与课程搜索`。

## 1. 交接结论

LearnHub 当前已经具备可启动、可演示的职业教育平台 MVP，核心页面和主要技术组件均已接通，能够完成注册登录、课程浏览与搜索、收藏/点赞、学习进度、问答发布、优惠券领取等基础体验。

但当前版本仍是“技术方案验证 + 产品原型”，不能直接作为公开互联网生产系统上线。主要原因如下：

- 部分业务状态仍保存在 JVM 内存中，服务重启后会丢失。
- 课程详情尚未形成完整的课程—章节—课时—视频学习闭环。
- Redis、RabbitMQ 和 Elasticsearch 已接入，但部分实现仍是演示级链路，缺少可靠消息、补偿、对账和全量重建能力。
- 用户中心和管理端以展示框架为主，统计数据和操作入口仍有占位内容。
- 尚未实现 OSS 视频上传、转码、鉴权播放、订单支付、审核、风控、生产部署和完整可观测性。

后续开发应继续采用“模块化单体”而不是立即拆微服务。优先补齐事实数据持久化、内容生产和学习闭环，再建设营销、搜索和上线保障。

## 2. 当前工程结构

```text
LearnHub/
├─ learnhub-common/        # 通用响应、异常等基础能力
├─ learnhub-pojo/          # 公共数据对象模块
├─ learnhub-server/        # Spring Boot 后端应用
├─ learnhub-web/           # Vue 3 前端
├─ sql/                    # MySQL 建表、种子和修复脚本
├─ deploy/                 # Docker Compose 与 Nginx 配置
├─ design-system/          # 当前 UI 设计规范
├─ docs/                   # 设计、实施和交接文档
├─ README.md               # 本地启动与功能说明
└─ AGENT.md                # 仓库开发与提交约定
```

基础架构原则：

```text
Vue Web
   │ /api
   ▼
Spring Boot 模块化单体
   ├─ MySQL：业务事实源
   ├─ Redis：令牌、幂等、库存和高频状态
   ├─ RabbitMQ：异步事件与流量削峰
   └─ Elasticsearch：可重建的搜索投影
```

## 3. 当前已经实现的功能

### 3.1 用户认证

已实现：

- 用户注册、登录、当前用户查询和退出。
- Spring Security 无状态认证。
- RS256 JWT 双令牌：Access Token 15 分钟、Refresh Token 7 天。
- Redis 刷新令牌白名单、刷新令牌一次性消费和 Access Token denylist。
- 前端 Axios 自动附加令牌；401 时进行刷新和请求重放。
- 登录弹窗、独立登录路由、注册页面和登录后用户信息展示。

当前边界：

- 未配置密钥时会临时生成 RSA 密钥对，仅适合本地开发；服务重启后旧令牌失效。
- `user_role` 表已经存在，但接口级 RBAC、管理员角色校验尚未真正落地。
- 未实现邮箱/手机号验证、找回密码、修改密码、登录设备管理、异常登录提醒和登录审计。
- 尚未实现验证码、登录限流、暴力破解防护和高风险操作二次认证。

### 3.2 课程与学习进度

已实现：

- MySQL 课程列表、分类筛选、关键词查询和课程详情基础数据。
- 课程、章节、课时、标签、课程标签和学习进度的数据表。
- 学习进度按用户与课时持久化，校验课时是否属于课程。
- 前端课程列表、课程详情、搜索区、标签入口、点赞和收藏交互。

当前边界：

- 课程详情接口当前主要返回课程表信息，尚未聚合章节、课时、讲师、试看权限和用户学习状态。
- 没有独立的真实学习播放页和播放器组件。
- 没有课程购买/报名、学习权限、有效期、试看策略和完课规则。
- 前端课程详情仍保留演示回退数据；这类 fallback 上线前必须移除或只在显式 mock 模式启用。
- 课程统计（学习人数、完课率、时长、评分）尚未形成可靠数据口径。

### 3.3 收藏与点赞

已实现：

- 收藏记录持久化到 MySQL，通过唯一索引保证幂等。
- 点赞使用 Redis Set 保存用户成员关系，可查询点赞状态和实时数量。
- 点赞变化可发送 RabbitMQ，消费者将增量聚合到 Redis Hash。
- 前端课程点赞、收藏状态可保存并在刷新后恢复。

当前边界：

- 点赞聚合增量尚未通过可靠定时任务批量落入 MySQL。
- 缺少 outbox、消息 ID、消费日志、重试/死信和批次幂等。
- Redis 不可用时会回退到单机内存集合；该状态无法跨实例共享，也会在重启后丢失。
- 尚未校验所有被点赞/收藏目标是否真实存在及是否允许互动。

### 3.4 问答社区

已实现：

- 登录用户发布问题。
- 问题可选择绑定课程，也可作为全站社区问题发布。
- 问题和回答以 MySQL 为事实源，服务重启后仍可查询。
- 问题列表分页、问题详情、回答分页、回答发布和回答计数原子更新。
- 问题及回答作者昵称通过用户数据真实聚合。
- 前端问答列表、提问弹窗、问题详情页、回答列表和回答输入入口。

当前边界：

- 尚缺少采纳操作、评论、举报、审核、编辑/删除和内容安全。
- 问答点赞仍未接入可靠事实表和计数对账。
- 仍需补充自动化 MySQL 集成测试、接口契约测试和并发回答计数测试。

### 3.5 优惠券与秒杀

已实现：

- 普通优惠券创建、列表和领取的演示接口。
- Redis Lua 对秒杀库存和重复领取进行原子校验及预扣。
- RabbitMQ 异步确认领取。
- Redisson 分布式锁保护确认临界区。
- Redis/消息中间件不可用时提供本地演示降级。

当前边界：

- 优惠券、领取记录和秒杀结果主要保存在内存 Map，尚未以 MySQL 表作为最终事实源。
- 数据库库存扣减、领取唯一约束、请求状态机、消息消费日志尚未串成真实事务。
- 缺少 publisher confirm、outbox、重试队列、死信队列、补偿脚本和定时对账。
- 服务重启后活动与领取状态可能丢失；当前实现不能用于真实营销活动。
- 未实现优惠券核销、订单抵扣、过期处理、退款返券和风控规则。

### 3.6 搜索

已实现：

- Elasticsearch 课程文档和索引写入接口。
- 关键词、标签、讲师匹配和点赞热度加权。
- 前缀联想接口。
- ES 为空或不可用时，会合并 MySQL 已发布课程，避免页面无结果。
- 前端搜索、快速标签和课程卡片展示。

当前边界：

- 当前搜索是在应用层加载文档后匹配和排序，不是完整的 ES `bool + multi_match + function_score` 查询。
- 联想目前不是正式的 completion suggester。
- 没有课程发布事件驱动的增量索引、版本控制、重试/死信和全量重建命令。
- 缺少分页、同义词、拼写纠错、搜索高亮、热搜词、搜索历史和排序回归数据集。
- ES 索引映射和中文分词插件需要作为部署的一部分固化。

### 3.7 前端体验

已实现页面：

- 课程列表与首页：`/courses`
- 课程详情：`/courses/:id`
- 问答列表：`/questions`
- 问题详情与回答：`/questions/:id`

- 管理端框架：`/admin`

已实现统一导航、登录态展示、响应式页面、平滑滚动、课程搜索和基础视觉设计。

当前边界：

- 个人中心的学习中、已完成、收藏、贡献等统计仍为静态数字。
- 最近学习区域仍是占位提示。

已实现：

- Docker Compose 编排 MySQL、Redis、RabbitMQ 和 Elasticsearch。
- Nginx SPA 与 `/api` 反向代理配置。

## 4. 当前数据持久化真相

后续开发必须先理解各模块真正的数据来源，不能仅根据页面效果判断完成度。

| 模块 | 当前主要数据源 | 是否可跨重启 | 生产化动作 |
| --- | --- | --- | --- |
| 用户 | MySQL | 是 | 补 RBAC、安全审计和账号安全 |
| Refresh Token/撤销 | Redis | 在 Redis 持久化正常时可保留 | 固化密钥、会话模型和故障策略 |
| 课程 | MySQL | 是 | 聚合章节课时、权限、统计和管理 CRUD |

| 收藏 | MySQL | 是 | 增加列表、目标校验和统计回写 |
| 点赞成员关系 | Redis Set | 依赖 Redis | 增加可靠消息、事实表和对账 |
| 问答 | MySQL | 是 | 增加采纳、审核、编辑/删除和集成测试 |
| 优惠券活动/领取 | JVM 内存 + Redis | 否/不完整 | 立即迁移到 MySQL 事实表 |
| 搜索 | ES + MySQL 回退 + JVM 缓存 | 部分 | 改为 ES 原生查询和可靠索引同步 |
| 用户中心统计 | 前端静态占位 | 否 | 建立聚合 API 与真实统计口径 |

## 5. 线上化目标架构

第一阶段仍使用模块化单体：

```text
浏览器 / 移动 Web
        │ HTTPS
        ▼
 CDN + WAF + Nginx / API Gateway
        │
        ▼
 Spring Boot 应用（至少 2 实例，无本地业务状态）
   ├─ MySQL 主库 + 备份/只读副本
   ├─ Redis 高可用
   ├─ RabbitMQ 高可用
   ├─ Elasticsearch 集群
   ├─ OSS/S3 + CDN（图片、附件、视频切片）
   └─ 日志、指标、链路追踪和告警
```

必须遵守：

- 应用实例无状态化，不允许用本地 Map 保存业务事实。
- MySQL 是用户、课程、问答、订单、优惠券和互动事实源。
- Redis 数据必须可以从 MySQL 或事件日志重建。
- ES 索引必须支持从 MySQL 全量重建。
- 任何关键异步消息都必须可追踪、可重试、可补偿、可对账。
- 媒体二进制不进入 MySQL，也不通过应用服务器长时间中转。

## 6. OSS 图片与视频能力设计

### 6.1 存储选型

建议定义统一 `ObjectStorageService`，屏蔽具体云厂商：

- 本地开发：MinIO。
- 生产：阿里云 OSS、腾讯云 COS、AWS S3 或兼容 S3 的对象存储。
- CDN：课程封面、头像和视频切片通过 CDN 分发。

不要在业务表中直接保存永久公网 URL，应保存 `provider + bucket + objectKey`，响应时生成 CDN 地址或短期签名 URL。

### 6.2 媒体数据模型

建议新增 `media_asset`：

| 字段 | 说明 |
| --- | --- |
| `id` | 媒体 ID |
| `owner_id` | 上传用户/管理员 |
| `biz_type`、`biz_id` | AVATAR、COURSE_COVER、LESSON_VIDEO、ATTACHMENT 等 |
| `provider`、`bucket`、`object_key` | 存储定位信息 |
| `original_name`、`content_type`、`size_bytes` | 文件元数据 |
| `sha256` | 秒传、去重和完整性校验 |
| `status` | UPLOADING、UPLOADED、PROCESSING、READY、FAILED、DELETED |
| `duration_seconds`、`width`、`height` | 媒体属性 |
| `cover_object_key`、`playback_manifest_key` | 视频封面与 HLS/DASH 清单 |
| `created_at`、`updated_at` | 审计时间 |

课程课时表只关联 `media_asset_id`，不要把转码过程耦合到课程表。

### 6.3 推荐上传流程

1. 前端调用 `POST /api/media/uploads`，提交文件名、大小、MIME、业务类型和哈希。
2. 后端校验用户权限、扩展名、MIME、大小和配额，创建 `UPLOADING` 记录。
3. 后端返回 STS 临时凭证或预签名直传 URL。
4. 浏览器分片直传 OSS，支持断点续传；文件流不经过应用服务器。
5. 前端调用完成确认接口，或由 OSS 回调通知后端。
6. 后端验证对象存在、大小和哈希，发布媒体处理事件。
7. 视频转码服务生成 HLS/DASH、多码率、首帧封面和字幕文件，更新为 `READY`。
8. 播放接口校验课程权限后返回短期签名播放地址。

### 6.4 视频生产能力

按优先级逐步实现：

- P0：MP4 直传、基础播放、上传进度、失败重试。
- P1：HLS 转码、多码率、自适应播放、封面抽帧、字幕上传。
- P1：CDN、防盗链、短期签名 URL、试看时长控制。
- P2：水印、DRM、转码任务优先级、内容审核、播放质量监控。

前端播放器可先选成熟方案，如原生 video + hls.js；只有业务需要时再引入付费播放器。播放进度按 10～30 秒或页面离开事件批量上报，避免每秒写库。

## 7. 用户中心扩展

个人中心应从当前展示页扩展为真正的用户工作台。

### 7.1 资料与账号安全

- 编辑昵称、简介、头像、职业方向和兴趣标签。
- 头像使用 OSS 直传、图片裁剪和缩略图。
- 修改密码、绑定邮箱/手机号、找回密码。
- 登录设备、会话列表、单设备退出和全部退出。
- 隐私设置、注销账号和数据导出。

### 7.2 学习工作台

- 最近学习与“继续学习”入口。
- 学习中的课程、已完成课程、学习时长和连续学习天数。
- 章节/课时完成度、课程总进度和最后播放位置。
- 收藏课程、点赞记录、浏览历史和学习计划。
- 证书或完课证明可放到后续阶段。

### 7.3 社区与资产

- 我的问题、我的回答、收到的点赞、消息通知。
- 我的优惠券、使用状态和过期提醒。
- 订单、支付记录、退款记录和发票（商业化阶段）。

建议接口：

```text
GET  /api/users/me/profile
PUT  /api/users/me/profile
GET  /api/users/me/dashboard
GET  /api/users/me/courses?status=learning|completed
GET  /api/users/me/favorites
GET  /api/users/me/questions
GET  /api/users/me/answers
GET  /api/users/me/coupons
GET  /api/users/me/sessions
DELETE /api/users/me/sessions/{sessionId}
```

统计数据应由后端返回，前端不得继续写死数字。

## 8. 课程内容与管理后台扩展

管理端是上线前的核心，不应只做页面展示。

### 8.1 课程内容模型

- 课程基本信息、封面、讲师、分类、标签、价格和上下架状态。
- 章节和课时拖拽排序。
- 视频、附件、图文内容和试看配置。
- 草稿、待审核、已发布、已下架状态机。
- 发布版本号和乐观锁，避免多人编辑覆盖。
- 课程发布后通过事务事件/Outbox 更新 ES。

### 8.2 后台权限

至少建立：

- `ADMIN`：系统管理。
- `OPERATOR`：课程和营销运营。
- `INSTRUCTOR`：维护自己负责的课程。
- `AUDITOR`：课程与问答审核。

后端必须使用 `@PreAuthorize` 或统一权限服务校验；前端隐藏按钮不能替代服务端授权。

### 8.3 推荐后台模块

- 课程、章节、课时和媒体管理。
- 讲师、分类和标签管理。
- 问答审核、举报处理和敏感词策略。
- 优惠券、秒杀活动和领取记录。
- 用户、角色、封禁与审计日志。
- 搜索索引重建、消息重试和数据对账入口。

## 9. 后续分阶段路线

### Phase 0：修正基线与移除假数据（P0）

目标：让页面展示严格反映后端真实状态。

- 将前端 fallback 数据限制为显式 mock 环境，线上请求失败展示错误和重试。
- 为现有 API 补统一错误码、分页结构和 traceId。
- 引入 Flyway 或 Liquibase，停止依赖一次性初始化脚本演进数据库。
- 建立 `local/test/prod` 配置和密钥管理规则。
- 增加后端接口集成测试和前端关键流程 E2E 测试。

验收：关闭任一依赖时页面能明确报错；数据库可从空库按版本迁移到最新；测试环境可重复创建。

### Phase 1：课程、媒体与真实学习闭环（P0）

目标：管理员能发布包含视频的课程，用户能学习并续播。

- 完成课程/章节/课时/标签管理 CRUD 和发布状态机。
- 接入 MinIO + 生产 OSS 抽象，完成封面、头像、视频直传。
- 增加媒体任务、转码状态、播放鉴权和播放器页面。
- 课程详情聚合章节、课时、试看与用户进度。
- 完成最近学习、续学入口和完课计算。

验收：从后台创建课程并上传视频，发布后前台可检索、播放、保存进度并继续学习。

### Phase 2：用户中心与权限（P0/P1）

目标：用户资料、学习数据和后台权限全部真实可用。

- 完成用户资料、头像、密码、会话和账号安全。
- 完成学习仪表盘、收藏列表、学习记录和社区贡献。
- JWT 加入稳定的角色/权限声明，并实现服务端 RBAC。
- 增加验证码、登录限流、操作审计和敏感操作二次校验。

验收：普通用户无法访问管理写接口；用户中心所有数字均来自后端真实数据。

### Phase 3：互动系统持久化（P0）

目标：问答和点赞在重启、多实例和消息重投下仍保持一致。

- [已完成] 将问题、回答迁移到 MySQL Mapper/Service，并移除生产路径内存数据源。
- [已完成] 增加问题详情、问题/回答分页、真实作者昵称与前端回答入口。
- [待完成] 增加采纳、编辑、删除、举报和审核。
- 为点赞实现 outbox 或可靠发布、事件 ID、消费日志、批量落库和对账。
- 删除生产环境的本地内存降级，改为明确失败、熔断和告警。

验收：服务重启不丢数据；重复点赞、取消和消息重投不造成计数漂移。

### Phase 4：优惠券与秒杀生产化（P0/P1）

目标：以 MySQL 为事实源完成真实高并发营销链路。

- 活动、库存、领取记录和秒杀请求全部持久化。
- 使用 requestId 和状态机返回异步结果。
- 实现数据库条件扣减、唯一索引和消费者事务。
- 增加 publisher confirm、outbox、延迟重试、死信、补偿与对账。
- 增加限流、设备/IP 风控和防刷。

验收：并发争抢不超卖、不重复领取；进程中断和消息重复后最终状态仍正确。

### Phase 5：搜索生产化（P1）

目标：ES 真正承担低延迟检索，而非应用层遍历。

- 使用原生 `bool + multi_match + filter + function_score`。
- 建立版本化索引和读写别名。
- 课程发布后以 outbox/MQ 增量更新索引。
- 提供全量重建、失败重试和索引延迟监控。
- 接入中文分词、completion suggester、同义词和高亮。
- 建立固定查询集做相关性回归。

验收：ES 清空后可以从 MySQL 一键重建；固定查询结果和排序符合预期。

### Phase 6：商业闭环（P1/P2）

目标：从免费内容平台扩展到可经营的线上教育平台。

- 课程 SKU、订单、支付、支付回调幂等和退款。
- 购买后课程权益、有效期、试看和退款回收。
- 优惠券核销和订单优惠分摊。
- 账单、对账、发票和运营报表。

涉及真实支付时，必须单独进行安全设计、回调验签、金额精度、幂等和财务对账评审。

### Phase 7：上线与运营保障（P0，贯穿前述阶段）

- 后端和前端容器镜像、CI/CD、灰度发布和自动回滚。
- HTTPS、域名、CDN、WAF、CORS/CSP 和限流。
- MySQL 备份恢复演练、Redis/RabbitMQ/ES 高可用。
- Prometheus/Grafana 指标、集中日志、错误追踪和告警。
- SLO：可用性、P95/P99 延迟、错误率和消息积压阈值。
- 依赖漏洞、镜像扫描、密钥轮换、最小权限和数据脱敏。
- 容量评估、压测、故障注入和灾难恢复演练。

## 10. 推荐优先级

| 优先级 | 工作 |
| --- | --- |
| P0 | 问答持久化、优惠券持久化、课程章节课时聚合、媒体/OSS、真实用户中心、后台 RBAC、移除假数据、数据库迁移、集成测试 |
| P1 | 点赞可靠落库、秒杀可靠消息、ES 原生查询与索引同步、账号安全、内容审核、监控告警 |
| P2 | 订单支付、推荐系统、证书、直播、IM、DRM、多租户和微服务拆分 |

不要先做微服务拆分。只有当单体模块边界稳定、团队需要独立发布，或压测证明某一模块必须独立扩缩容时再拆分。

## 11. 测试与验收基线

每个线上化模块至少具备：

- 单元测试：业务规则、状态机、权限、幂等。
- 数据库集成测试：唯一约束、事务、迁移脚本。
- 中间件集成测试：Redis Lua、RabbitMQ 重投、ES 查询。
- API 测试：认证、校验、错误码和分页。
- 前端 E2E：登录、选课/购买、播放、续学、互动和退出。
- 并发测试：秒杀、点赞、刷新令牌和进度上报。
- 故障测试：Redis/ES/RabbitMQ 暂停、消费者重启、消息重复。

常用本地验证：

```powershell
docker compose -f deploy/docker-compose.yml up -d
D:\Android\apache-maven-3.9.10\bin\mvn.cmd test
D:\Android\apache-maven-3.9.10\bin\mvn.cmd verify
cd learnhub-web
npm run build
```

## 12. 新对话接手时的执行约定

新的开发对话开始工作前应：

1. 完整阅读根目录 `AGENT.md`、`README.md` 和本文。
2. 执行 `git status --short`，保护已有未提交修改。
3. 以代码、SQL 和测试为当前事实，不把 `MVP_IMPLEMENTATION.md` 中的规划误认为全部已实现。
4. 先定位当前模块的数据事实源，禁止继续增加 JVM 内存业务状态。
5. 修改数据库结构时增加版本化迁移和回滚说明。
6. 修改 API 时同步前端类型、Swagger、测试和本文状态。
7. 完成一个可验证的逻辑修改后立即使用中文 Conventional Commit 提交。
8. 未经明确要求不要推送远端，不要提交密钥、令牌、`.env`、构建产物或测试账号。
