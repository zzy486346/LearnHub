## 日志文件怎样逐行处理

来源标识：generated.course.12016.lesson.32161

### 大日志处理的基本思路

依据课程目录编写的AI生成学习资料，非原授课逐字稿。日志可能有数 GB，若用 read() 或 readlines() 一次装入内存，程序会占用接近文件大小甚至更多的空间，还可能触发交换或被系统终止。Python 文件对象本身就是可迭代对象，使用 with open(path, encoding='utf-8') as file，再写 for line in file，可以按缓冲区逐步读取。课程主题是把解析、过滤和聚合放进单行流水线，让内存规模主要取决于当前行与必要统计状态，而不是文件总大小。

### 逐行解析的机制

with 语句确保正常结束或抛异常时关闭文件。每次迭代得到一行字符串，可先 strip 行尾，再根据格式解析。结构化 JSON Lines 可逐行 json.loads；固定分隔日志可用 split 并限制最大切分次数；复杂格式可用预编译正则，但应处理不匹配行。解析失败不宜让整批静默中断，可以累计错误计数并记录有限样本。若日志可能包含非法字节，应明确 errors 策略，同时保留错误可观测性，避免用 errors='ignore' 悄悄改变证据。

### 可执行统计示例

目标是统计每种 HTTP 状态码。初始化 Counter，逐行提取 status 后执行 counts[status] += 1；无需保存所有日志。若只关心 5xx，可以解析后立即 continue 过滤其他行。处理多个文件时用 pathlib 遍历明确文件列表，并按稳定顺序读取。为了显示进度，可累加处理字节数或行数，但不要频繁打印导致 I/O 成为瓶颈。超长单行仍可能占用较多内存，因此对不可信输入可设置允许的最大行长并把异常行隔离。

### 边界、编码与轮转误区

逐行读取不表示零内存，只表示不随总文件大小线性增长；聚合维度若无限增长，例如把每个随机请求 ID 都存入字典，仍会耗尽内存。读取正在写入的日志时，要区分读到当前 EOF 与文件永久结束；轮转后原文件描述符可能仍指向旧文件。二进制压缩日志可通过 gzip.open 以流方式解压，但损坏时要报告文件位置。不要在解析阶段直接覆盖原日志，也不要假设每行都有完整字段，真实数据常含截断、空行和多行堆栈。

### 自测与参考答案

自测一：为什么 for line in file 比 readlines() 更适合大文件？参考答案：它按流迭代，不把全部行同时保存在列表中。自测二：逐行处理为何仍可能内存上涨？参考答案：聚合字典等状态可能随唯一键数量增长。自测三：遇到一行格式错误是否应忽略所有异常？参考答案：不应，应计数、保留有限错误样本并继续或按策略失败。测试可构造空文件、非法行、超长行、混合编码提示和百万行输入，确认结果正确且内存保持有界。

## 统计报告如何稳定生成

来源标识：generated.course.12016.lesson.32162

### 稳定报告包含哪些保证

依据课程目录编写的AI生成学习资料，非原授课逐字稿。自动化报告不仅要数值正确，还要在相同输入下产生相同顺序、明确格式，并在写入失败时保留上一份完整报告。若字典遍历顺序依赖数据到达先后，两个内容相同的输入可能得到不同文件，难以审查和版本比较。若直接打开目标文件覆盖，程序写到一半崩溃，使用者会看到截断内容。课程主题因此把统计聚合、确定性排序、临时文件写入和原子替换串成可重复流程。

### 聚合与确定性排序

先把输入转换为明确的统计记录，例如 department、success_count、failure_count 和 total。排序必须写出所有关键规则：先按 failure_count 降序，再按 department 升序作为平局规则。只写 reverse=True 可能把第二关键字也反向，可用 key=lambda x: (-x.failure_count, x.department)。日期、数字不要先转成不统一的展示字符串再排序。输出 CSV 时明确列顺序、编码和换行，输出 JSON 时固定必要字段，并决定是否排序键，避免环境差异影响结果。

### 临时文件与原子替换示例

生成 report.csv 时，先在同一目标目录创建临时文件，完整写入并 flush，必要时执行 fsync，然后用 os.replace(temp_path, target_path) 替换目标。将临时文件放在同一文件系统，才能利用重命名通常具备的原子可见性：读取者看到旧版本或新版本，而不是半份内容。异常时在 finally 中只清理本次临时文件，不删除原报告。若有多个生成进程，还需要锁、唯一任务约束或版本化输出，单靠原子替换不能决定谁应成为最终版本。

### 精度、时间与可追溯边界

金额统计应使用 Decimal 或最小货币单位整数，避免二进制浮点累加产生尾差。时间范围要明确时区和边界，例如左闭右开 [start,end)，防止跨日报表重复或漏算。报告可记录输入文件清单、生成时间、统计窗口和程序版本，但生成时间会让字节内容每次不同，需根据可重复性要求决定是否加入。不要把“成功写文件”当作统计正确的证明；聚合规则必须有独立测试，写入与替换也要通过故障注入验证。

### 自测与参考答案

自测一：两个部门失败数相同，怎样保证顺序稳定？参考答案：增加明确的第二排序键，例如部门名称升序。自测二：为何临时文件应与目标在同一文件系统？参考答案：跨文件系统移动可能退化为复制，无法提供同样的原子替换语义。自测三：写入中途异常时目标文件应是什么状态？参考答案：上一份完整报告仍可用，临时文件被清理。测试应固定输入多次生成并比较内容，还要模拟写入异常、目标已存在和并发生成。
