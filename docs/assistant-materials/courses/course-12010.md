## 接口连不上先查哪里

来源标识：generated.course.12010.lesson.32101

### 分层排查概览

本资料依据课程目录编写，是 AI 生成的学习资料，非原授课逐字稿。接口“连不上”可能发生在域名解析、路由、防火墙、端口监听、反向代理、应用进程或下游依赖任一层。高效排查应先固定客户端、目标地址、时间和具体错误，再从离请求最近且验证成本低的层开始逐层确认。连接超时、连接被拒绝、TLS 失败和 HTTP 500 指向的层级不同。

### 从网络到监听端口

先用域名解析工具确认目标 IP，再用 curl -v 查看连接、TLS 和 HTTP 阶段。超时通常表示路径或防火墙丢包，也可能服务严重卡顿；立即拒绝常表示目标可达但端口无人监听。登录服务器后用 ss -lntp 查看端口、监听地址和进程。只监听 127.0.0.1 的服务不能直接接受外部连接；监听 0.0.0.0 也不代表安全组和防火墙已经放行。

### 一条可执行的诊断路径

假设访问 https://example.test/api 超时：先记录 curl 的解析 IP；从客户端测试目标 443；在服务器确认代理进程和 443 监听；本机 curl 代理入口；再从代理所在环境访问后端地址和健康接口。若本机后端正常、外部代理失败，检查代理 upstream、网络命名空间和规则；若端口存在但健康接口 500，则进入应用日志、配置和数据库连接排查，而非继续修改防火墙。

### 误区与操作边界

ping 不通不能单独证明主机不可达，因为 ICMP 可能被禁；ping 通也不能证明 TCP 端口开放。不要一开始就重启服务，重启会抹去现场并可能短暂掩盖根因。查看日志应围绕故障时间和请求标识，避免只读最后一行。生产环境抓包、修改防火墙或绑定地址会影响安全和流量，应遵循变更流程。排查过程中每一步都记录预期、实际结果和下一层假设。

### 自测与参考答案

自测一：curl 显示 Connection refused 优先查什么？参考答案：目标地址上的端口监听、进程和端口映射，因为网络已快速返回拒绝。自测二：ss 显示服务只监听 127.0.0.1:8080 有何含义？答案是通常仅本机可访问，外部入口需经代理或调整绑定。自测三：返回 HTTP 500 还应先查防火墙吗？答案通常不应，HTTP 响应说明网络链路已到应用，应转查应用日志和依赖。演练时可分别制造错误域名、未监听端口、只绑定回环地址、代理上游写错和应用返回五百五种故障，为每种情况保存客户端错误与服务端证据。再按统一检查表定位，统计在哪一步首次发现异常。这样能形成从现象到层级的稳定映射，也避免靠反复重启碰运气。

## 资源升高怎样缩小范围

来源标识：generated.course.12010.lesson.32102

### 资源排查概览

本资料依据课程目录编写，是 AI 生成的学习资料，非原授课逐字稿。服务器变慢时先区分 CPU、内存、磁盘 I/O、网络和负载队列，不要把 load average 直接等同于 CPU 使用率。排查目标是把系统现象收窄到进程、线程、文件或请求，并建立时间关联。一次瞬时快照可能错过波峰，因此要结合监控曲线、故障时间和多次采样。

### CPU 与负载怎么读

uptime 展示平均负载，top 可查看 CPU 用户态、系统态、I/O 等待和进程排序。高 CPU 时按 CPU 找进程，再在支持的工具中观察其线程；高 load 但 CPU 空闲可能有大量不可中断 I/O 等待。进程使用多个核心时，CPU 百分比可能超过 100%。定位到 Java 线程后还需结合线程转储或性能分析，不能只凭线程编号猜测具体方法。

### 内存与磁盘的示例路径

free -h 可看可用内存，不能把 free 列很小直接当作泄漏，因为 Linux 会利用内存做缓存。按 RSS 找到持续增长进程，再结合应用堆、堆外内存和映射分析。磁盘满时先用 df 看文件系统，再用 du 在明确目录逐层收窄；若 df 高而 du 对不上，检查被删除但仍由进程打开的文件。iostat 可帮助区分设备繁忙和应用只是大量写日志。

### 边界与常见误区

kill -9 会立即终止进程，可能破坏正在写入的数据，也丢失诊断现场；应先采样并尝试正常终止。释放 page cache 不是通用优化，会使后续读取重新访问磁盘。单看内存百分比无法区分可回收缓存与不可回收占用。日志文件删除后空间未释放时，应让持有进程重新打开文件或按流程重启，而不是反复删除。任何压力工具和转储操作都要评估磁盘与性能影响。

### 自测与参考答案

自测一：load 很高但 CPU 大多空闲应关注什么？参考答案：不可中断任务和 I/O 等待，继续看磁盘、网络存储及进程状态。自测二：free 很小是否必然内存不足？答案不是，应重点看 available、交换活动和进程增长趋势。自测三：df 显示磁盘满而 du 汇总很小的可能原因？答案是文件已从目录删除但仍被进程打开，占用块尚未释放；可查看开放文件并安全处理持有进程。练习可用受控程序分别制造计算繁忙、缓慢写盘和逐步占用内存，连续采样一分钟。记录系统指标、进程排序和现象，结束程序后确认资源恢复。再比较单次 top 截图与连续曲线的差异，说明为什么定位必须保留时间维度。测试仅在隔离环境执行，并预设资源上限与终止条件。
