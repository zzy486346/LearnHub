## 理解 Token 与上下文窗口

来源标识：generated.course.1002.lesson.3005

### 概念入门与课程主题

来源声明：本资料依据课程目录编写，是 AI 生成学习资料，非原授课逐字稿。大模型接收和生成的基本计量单位是 Token，它不等同于字符或汉字。文本会先被分词器编码为 Token 序列，模型再基于序列预测后续内容。上下文窗口表示一次推理中模型可处理的输入与输出总容量。本课程从大模型应用工程出发，关注长度预算如何影响费用、延迟、记忆和回答完整性。

### 窗口与预算机制

一次请求通常包含系统指令、历史对话、检索材料、当前问题以及预留输出。它们共同占用上下文窗口。若输入已经接近上限，可供输出的空间就会减少，服务也可能拒绝请求。工程上要分别控制输入字节、估算 Token 和最大输出 Token。精确数量必须由对应模型的分词器计算；用字符数或 UTF-8 字节只能做保守预算，不能宣称是精确费用。

### 可手推示例

假设某模型上下文上限为 8000 Token，系统指令占 500，历史占 1800，检索片段占 3200，当前问题占 200，并预留 1200 输出，总计 6900，仍有 1100 余量。如果再加入 2000 Token 文档就会超限。可按优先级处理：保留系统规则和当前问题，裁剪较旧历史，对检索结果去重并只保留高相关片段，最后确保输出预留。实际实现还要在发送前做硬上限校验。

### 常见误区与边界

同一句文本在不同模型或分词器下 Token 数可能不同，不能用固定的“一个汉字等于一个 Token”估算。扩大窗口不能自动提升回答质量，低相关材料过多会稀释重点并增加延迟。历史记录持久化也不意味着每次全部发送给模型，应有界选择并重新校验权限。max output tokens 是输出上限，不保证模型一定使用完。流式传输只改变接收方式，不会绕过窗口与计费限制。

### 自测与参考答案

自测一：上下文窗口包含输出吗？参考答案：通常包含本次输入与生成输出的总 Token。自测二：发现请求接近上限，首先应保留什么？参考答案：系统约束、当前问题和最相关证据，再压缩旧历史。自测三：为什么项目仍设置字节上限？参考答案：它能在精确 tokenizer 不可用时提供稳定的传输与资源保护，但只能作为保守近似。评估时应同时记录输入、输出、耗时和失败原因。

## 从 Prompt 到结构化输出

来源标识：generated.course.1002.lesson.3006

### 概念入门与课程主题

来源声明：本资料依据课程目录编写，是 AI 生成学习资料，非原授课逐字稿。Prompt 是向模型说明角色、目标、上下文、约束和输出格式的输入。应用开发不只追求“回答看起来不错”，还要让结果能被程序稳定解析。结构化输出通常以 JSON 或确定字段对象承载，例如 answer、citations、confidence。完整链路包括定义模式、提供必要证据、请求模型生成、解析校验以及失败后的受控处理。

### 约束与解析机制

系统指令适合放长期不变的安全规则和输出契约，用户消息承载本次问题，检索证据应有清晰边界和编号。模式应明确字段类型、必填项、枚举和长度限制。模型输出后不能直接信任，要先进行 JSON 解析，再做 schema 或 Java Bean 校验，最后执行领域校验，例如引用编号必须来自本轮证据。解析失败可以在预算内请求模型修复，但修复输入不应泄露内部异常和敏感信息。

### 可执行示例

要求模型输出 {"answer":"...","citations":["E1"]}。Prompt 明确 answer 使用中文，citations 只能选 E1 到 E3，没有依据时 answer 固定为资料不足且 citations 为空。Java 侧先用 JSON 解析器映射为响应对象，校验 answer 非空、引用无重复并属于允许集合。若模型返回 markdown 代码围栏或多余说明，解析应失败并进入一次受控修复，而不是用脆弱的字符串截取猜测。

### 常见误区与边界

在 Prompt 中写“务必返回 JSON”并不能替代服务端校验。temperature 调低可降低随机性，但不能保证永不违约。结构合法也不代表事实正确，仍需引用、权限和版本检查。不要把用户原文直接拼入系统指令，否则容易形成提示注入边界混乱；应以独立消息或明确分隔区传递。不应无限重试解析失败，因为每次调用都消耗时间与预算，达到上限后要返回明确失败。

### 自测与参考答案

自测一：结构化输出要经过哪三类检查？参考答案：语法解析、字段模式校验和业务领域校验。自测二：引用字段为什么不能只检查非空？参考答案：还必须确认编号来自本轮已授权证据。自测三：修复请求何时停止？参考答案：达到模型调用、时间或 Token 预算时停止并记录失败。测试应覆盖正确 JSON、缺字段、错误类型、未知引用和夹带额外文本等情况。

## 构建文档切分与向量索引

来源标识：generated.course.1002.lesson.3007

### 概念入门与课程主题

来源声明：本资料依据课程目录编写，是 AI 生成学习资料，非原授课逐字稿。RAG 先从资料库检索相关内容，再把证据交给模型生成回答。文档通常不能整篇直接建立一个向量，因为主题可能过多且长度超过模型限制，因此需要切分成语义相对完整的片段。索引既可以是关键词倒排索引，也可以是向量索引；二者可独立使用或混合召回。本课聚焦切分、嵌入、存储和可追溯元数据。

### 切分与索引机制

切分应优先利用标题、段落和列表等自然边界，再用最大长度与适度重叠控制片段。每个片段保存 courseId、lessonId、documentId、version、chunkIndex 和正文摘要。向量模型将片段与查询编码到同一向量空间，通过相似度寻找邻近内容。索引是可重建投影，原始资料和版本状态应由事实库维护；重新发布资料后，要生成新版本片段并让旧版本退出当前检索。

### 可手推示例

一篇包含“缓存穿透”“缓存击穿”“缓存雪崩”三个二级标题的讲义，可先按标题分成三段。若“缓存击穿”段仍过长，再按自然段切成两个片段，并保留少量重叠使上下文连贯。写入索引时记录 documentId=42、version=3、chunkIndex=1。用户查询“热点键失效怎么办”时召回该片段，服务端再用 documentId 和 version 到事实库确认它仍是当前可读版本，才交给模型。

### 常见误区与边界

片段越小不一定越好，过小会丢失定义与条件；过大则主题混杂、召回不精确。重叠过多会产生大量重复结果和额外成本。向量相似不等于事实相关，仍需课程、权限和状态过滤。不要只在向量库保存文本而丢掉事实库标识，否则无法可靠撤回或复核版本。更换嵌入模型后向量空间通常不兼容，应建立新索引并重新计算，而不是混用旧向量。

### 自测与参考答案

自测一：为什么片段必须带 documentId 和 version？参考答案：用于回查原始资料、确认当前版本并支持撤回。自测二：标题边界为何优先于固定字符数？参考答案：更可能保留完整语义单元。自测三：向量库应成为资料事实源吗？参考答案：不应，它是可重建检索投影，事实状态由主数据库维护。验收要检查片段覆盖、重复率、版本切换和删除资料后不再召回。

## 评估检索质量与回答效果

来源标识：generated.course.1002.lesson.3008

### 概念入门与课程主题

来源声明：本资料依据课程目录编写，是 AI 生成学习资料，非原授课逐字稿。RAG 质量包含两个相互关联但必须分开的部分：检索是否找到了需要的证据，回答是否正确使用证据。只看最终文字顺畅程度会掩盖检索缺失，也无法判断模型是否凭常识猜测。本课建立离线评测集，记录问题、期望资料和可接受答案要点，并观察检索、生成、引用和拒答四类表现。

### 指标与分层机制

检索层可用 Recall@K 判断前 K 个结果是否覆盖标注相关片段，用 Precision@K 观察噪声比例，并记录排序位置。回答层检查事实正确性、与证据一致性、问题覆盖度和引用有效性。对于资料库无法回答的问题，应评估系统能否准确拒答；这类题可暴露模型脱离证据自由发挥的问题。线上还要监测延迟、失败率、调用次数和预算消耗，但这些不能替代质量评测。

### 可手推示例

准备十个问题，每题标注一个或多个相关片段。某题前五个结果中包含目标片段，则 Recall@5 命中；若前三个只有一个相关结果，Precision@3 为三分之一。随后让模型基于同一结果回答，由评审检查关键结论是否出现在证据中、引用编号能否回到当前版本。再加入两道资料外问题，期望结果是明确说明资料不足。比较修改切分或排序前后的同一批指标，避免凭个别示例判断。

### 常见误区与边界

命中一个相关片段不代表检索已经充分，问题可能需要多段证据。自动评分模型也可能误判，关键样本要人工复核。评测集如果来自开发者反复调参使用的同一批问题，会产生过拟合，应保留独立留出集。不能因为模型用常识答对就把无证据回答算作 RAG 成功。引用存在也不代表引用支持结论，需要检查蕴含关系。数据权限场景还应把越权资料召回视为严重失败。

### 自测与参考答案

自测一：检索和回答为何分开评估？参考答案：找不到证据与错误使用证据需要不同修复措施。自测二：资料外问题的正确表现是什么？参考答案：明确拒答或说明资料不足，不能无依据补全。自测三：调参为何要留出集？参考答案：防止只适配已知问题而高估泛化能力。一次完整报告应包含样本范围、指标定义、基线、变更结果、失败案例和权限检查。
