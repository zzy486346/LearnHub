### Redis、缓存与 Lua 概览

依据课程目录编写的AI生成学习资料，非原授课逐字稿。Redis 是以内存数据结构为核心的键值数据存储，常用于缓存热点数据、计数、排行榜、限流和短期状态。常见结构包括字符串 String、哈希 Hash、列表 List、集合 Set、有序集合 Sorted Set，以及流 Stream 等。缓存能减少后端数据库读取压力，但要处理过期、穿透、击穿和数据一致性。Lua 脚本允许把多条 Redis 命令作为一个整体在服务器端连续执行，适合库存“检查后扣减”这类不能被其他命令插入的逻辑。

### Lua 原子执行的机制与限制

Redis 执行脚本期间不会穿插处理其他客户端命令，因此读取库存、判断和扣减之间不会被并发请求打断。脚本应短小，避免长时间阻塞 Redis。原子执行不等于关系数据库事务：Lua 脚本发生运行时错误时，Redis 不会自动回滚错误发生前已经执行的写命令。因此要先完成参数、键类型、存在性和业务条件检查，再执行真正写入，并避免在写入后调用可能报错的命令。脚本也不能替代库存最终事实库的一致性方案。

### 库存预扣脚本的可手推流程

调用前约定 KEYS[1] 是库存键，ARGV[1] 是扣减数量。脚本先把 ARGV[1] 转成数字，若转换失败或数量不是正整数则返回参数错误；再读取库存，键不存在返回未初始化；若值不是合法非负整数则返回数据错误；当库存小于请求量时返回不足；全部检查通过后执行 DECRBY，并返回扣减后的库存。示例库存 5、请求 2，结果为 3；库存 1、请求 2，返回不足且库存仍为 1。键名通过 KEYS 传入，便于集群环境按键路由，不应把动态键藏在 ARGV 后随意访问。

### 幂等、重试与业务边界

即使脚本原子，客户端超时也可能处于“服务端已扣减但客户端没收到结果”的未知状态。若直接重试，会再次扣库存。可传入业务请求号，并在同一脚本中先检查幂等记录：已处理则返回原结果，未处理才扣减并记录；幂等记录要设计过期与容量。库存键存在且非负只是 Redis 侧约束，订单取消、支付失败和数据库落单仍需要确认、补偿与对账。预扣成功不等于最终成交，也不能把 Redis 的高可用切换误认为绝不丢失最近写入。
