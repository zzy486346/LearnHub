## 优惠券规则如何写单元测试

### 单元测试关注规则行为

依据课程目录编写的AI生成学习资料，非原授课逐字稿。优惠券规则通常包含有效期、最低消费、折扣方式、适用商品、用户资格和叠加限制。单元测试应把规则对象作为一个小范围单元，用明确输入验证可观察结果，不依赖真实数据库、网络或当前系统时间。测试目的不是逐行复制实现，而是锁定业务行为：哪些订单可用、优惠金额如何计算、哪些边界必须拒绝，以及失败时返回什么原因。

### 等价类与边界设计

以满 100 减 20、有效期到 6 月 30 日为例，金额可分为小于 100、等于 100、大于 100 三类；时间可分为开始前、开始时、有效期内、结束时和结束后；商品可分为全部适用、部分适用和完全不适用。边界值最容易暴露大于与大于等于、时区和小数舍入错误。测试名称应表达条件与结果，例如 shouldApplyTwentyDiscountWhenEligibleAmountEqualsThreshold，而不是 test1。

### 可执行测试结构示例

Arrange 阶段构造固定 Clock、优惠券和订单；Act 调用 calculateDiscount；Assert 同时检查是否可用、优惠金额和失败码。金额使用 Decimal 或最小货币单位，避免 0.1 的浮点误差。参数化测试适合把 99.99→0、100.00→20、150.00→20 等表格化。若规则规定优惠不得超过适用商品金额，还要加入低价商品组合。异常输入如负金额、空商品和缺失用户不应通过随机 NullPointerException，而应验证约定的校验结果。

### 隔离误区与测试边界

单元测试不应连接真实数据库，也不应使用 now() 导致跨天失败；把时间和外部资格查询作为依赖注入。模拟对象只用于边界依赖，不要把每个内部方法都 mock，否则重构实现会让测试大面积破裂。只测正常路径不能证明规则可靠，且覆盖率百分比不代表业务边界已覆盖。多个优惠券叠加属于组合规则，若职责已超出单个规则对象，可以在更高层另写组合测试，不必把所有场景塞进一个巨型单测。

### 自测与参考答案

自测一：满 100 可用时，100.00 是否必须单独测试？参考答案：必须，它是包含关系的关键边界。自测二：为何注入固定 Clock？参考答案：让有效期判断可重复，不受运行日期与时区影响。自测三：覆盖率 100% 是否说明优惠规则正确？参考答案：不说明，断言可能薄弱且遗漏等价类。建议至少覆盖门槛、有效期、适用范围、资格、封顶、舍入、空值与非法值，并让每个失败用例检查明确原因。

## 领取接口怎样做集成验证

### 集成验证关注跨层协作

依据课程目录编写的AI生成学习资料，非原授课逐字稿。领取优惠券看似一个 HTTP 请求，实际穿过认证、参数校验、应用服务、库存扣减、用户领取记录和数据库约束。单元测试能验证各自规则，却不能证明映射、事务和真实 SQL 能协作。集成测试应启动足够真实的应用边界与临时基础设施，通过接口提交请求，再查询事实状态。目标是验证一个完整行为切片，而不是把所有外部服务都接到生产环境。

### 测试环境与数据机制

测试使用独立数据库或一次性容器执行正式迁移，插入明确优惠券、用户和库存。通过真实认证流程或受控测试身份调用 POST /coupons/{id}/claim，断言状态码、响应体、领取记录和剩余库存。每个测试要隔离数据，可采用回滚、唯一业务编号或重建容器，但异步消息跨事务时要理解回滚范围。数据库版本应与实际运行环境相近，内存数据库可能掩盖锁、索引和 SQL 方言问题。

### 成功、重复和并发示例

库存初始为 1。第一次合法领取应返回成功，库存变 0，并产生一条 user_coupon。相同用户携带同一幂等键重试，应返回同一业务结果且记录仍为一条。两个不同用户并发抢最后一张券时，只允许一个成功，另一个得到已领完，最终库存不能为负。可用 CountDownLatch 或并发客户端同时放行请求，再等待全部结果。数据库唯一约束与条件更新应作为最后防线，测试不能只断言两个响应，还要核对最终持久化状态。

### 常见误区和外部边界

仅 mock Repository 的控制器测试不能称为完整集成验证。只看 200 响应也不足以证明事务正确；接口可能返回成功却没有提交，或失败后残留半条数据。并发测试若没有同步起跑，可能只是两个串行请求。消息通知若采用事务后发布，应验证提交后事件，失败补偿则可用可控 fake 或测试 broker，但不要把第三方真实短信费用带入测试。测试日志和断言不能打印令牌、密码或用户敏感信息。

### 自测与参考答案

自测一：为什么不只断言响应体？参考答案：还要验证库存与领取记录等事实状态，确认事务一致。自测二：内存数据库为何可能不够？参考答案：锁语义、约束和 SQL 方言可能与实际数据库不同。自测三：库存 1 的两个并发请求期望什么？参考答案：一个成功、一个失败，最终库存 0 且只有一条有效领取。完整用例还应覆盖未登录、优惠券不存在、未开始、已过期、用户限领和重复请求。
