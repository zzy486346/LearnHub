## 课程状态如何避免魔法字符串

来源标识：generated.course.12013.lesson.32131

### 类型建模概览

本资料依据课程目录编写，是 AI 生成的学习资料，非原授课逐字稿。魔法字符串是散落在代码中的裸文本，例如 'draft'、'published'，拼写错误只能到运行时暴露。TypeScript 字符串字面量联合类型可把允许值收紧为有限集合：type CourseStatus = 'DRAFT' | 'PUBLISHED' | 'ARCHIVED'。变量、函数参数和对象字段都复用该类型，编辑器即可提示并检查。

### 联合类型与穷尽检查

定义 interface Course { id:number; status:CourseStatus } 后，renderStatus(status) 的参数不能接收任意 string。使用 switch 处理各状态，并在 default 把值赋给 never，可在以后新增状态但漏写分支时产生编译错误。若还需要展示标签，可用 Record<CourseStatus,string> 建立完整映射，编译器会要求每个合法状态都有标签，也会拒绝多余或拼错的键。

### 从常量派生类型示例

可声明 const COURSE_STATUS = ['DRAFT','PUBLISHED','ARCHIVED'] as const，再用 typeof COURSE_STATUS[number] 派生联合类型，运行时校验与编译期类型共享同一来源。表单选项遍历该常量，接口数据进入页面时先判断 includes；通过类型守卫后才能视为 CourseStatus。这样既避免手工维护两份列表，也明确外部字符串在校验前仍是不可信的 string。

### 边界与常见误区

TypeScript 类型在运行时会被擦除，后端返回 'UNKNOWN' 时不会自动被拦截，因此边界校验不可省略。enum 也能表达有限状态，但会生成运行时代码，团队可按序列化和风格选择；联合类型更轻量。不要使用 as CourseStatus 强行断言未知响应，这只是关闭检查。状态不仅是标签，若迁移有业务规则，还应定义允许的状态转换并由服务端最终校验。

## 接口响应怎样安全进入页面

来源标识：generated.course.12013.lesson.32132

### 边界数据课程概览

本资料依据课程目录编写，是 AI 生成的学习资料，非原授课逐字稿。TypeScript 能检查本地代码，却不能保证服务器真实返回的数据符合接口声明。安全做法是把网络响应视为 unknown，在系统边界完成结构、字段类型和枚举值校验，再转换为页面内部模型。这样能把错误拦在入口，并使组件只处理稳定、已经规范化的数据，而不是到处写可选链和断言。

### 外部 DTO 与内部模型

外部 DTO 应贴近传输格式，例如 id 可能是字符串、createdAt 是 ISO 文本、status 是未知字符串；内部 CourseModel 可规定 id 为 number、createdAt 为 Date、status 为 CourseStatus。解析函数先确认值是非空对象，再逐字段判断，完成字符串到数字、日期的转换，并对缺失可选字段给默认值。失败时返回明确错误或结果类型，不把半合法对象直接塞进状态。

### 可执行的校验流程

请求函数取得 response.data 后保持 unknown，调用 parseCourseList。解析器先检查顶层是数组，再对每项验证 id、title、status；status 通过 isCourseStatus 类型守卫，日期用 Date 构造后确认不是无效值。全部通过才返回 CourseModel[]。页面的 loading、success、empty、error 状态分开表达，校验失败记录不含敏感数据的字段路径，并向用户显示可恢复提示。

### 常见误区与边界

把 axios.get<CourseModel[]> 的泛型写上去只是在编译器中声明期望，并未验证网络内容；使用 data as CourseModel[] 同样会掩盖风险。校验库可减少样板代码，但仍要设计清楚外部与内部模型以及错误策略。不能无条件把服务端未知字段透传到 DOM。对于超大响应，要限制体积并考虑流式或分页，避免校验前已耗尽内存。契约测试能减少变化，但不替代运行时防御。

### 自测与参考答案

自测一：为什么网络数据用 unknown 比 any 安全？参考答案：unknown 在读取属性前要求缩小类型，any 会关闭检查。自测二：泛型 get<Course[]> 是否完成运行时验证？答案没有，它只影响静态推断。自测三：服务端 id 返回 '42'，内部希望 number 怎么办？答案是在边界解析并验证可转换性后生成 number；无法转换则返回解析错误，不应在各组件中分别隐式转换。页面内部因此能依赖统一模型。实践可准备五份响应：完全合法、缺标题、编号不可转换、未知状态、日期无效，逐一验证解析结果和页面错误态。再让服务端增加一个页面暂不使用的字段，确认解析器能按兼容策略忽略它；若删除必需字段则应明确失败。最后检查错误日志只记录字段路径和请求标识，不把完整用户数据或令牌写入日志。
